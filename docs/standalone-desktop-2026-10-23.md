# Windows 独立桌面版

完整桌面包包含 `ProofCode.exe` 和旁边的 `standalone/` 目录。首次打开时，桌面端会在当前 Windows 账户目录创建本机 H2 数据库和随机密钥，并启动内置控制面与 Agent Runner；模型供应商仍需在“Agent 设置”中填写 API 地址、协议、模型和 API Key。

独立模式不启动 Docker、PostgreSQL、Redis 或 Artemis。它保留同一套项目、对话、上下文记忆、自定义 Agent、Skills、MCP、审批、补丁、测试验证、事件和历史检索接口。关闭应用时只停止本次启动的 Java/Runner 子进程，任务状态和检查点留在本机数据目录，下一次打开可继续。

将 `ProofCode.exe` 与 `standalone/` 一起放置，不要单独移动 exe。`desktop/package-standalone-release.ps1` 可生成组合 ZIP。包内包含裁剪 Java 17、MinGit、ripgrep、控制面 JAR、Runner 和 MCP inspection helper；发布前会校验固定 SHA-256。

Windows 需要 WebView2。模型请求需要可访问所配置的供应商；项目使用的 Node、Python、Go 等编译器/测试工具以及自定义 MCP 服务所需依赖，应按该项目另行提供。应用自身的启动无需安装 Node、Go、Java、Git 或 Docker。

数据默认位于 `%APPDATA%\ProofCode\standalone`，包括文件数据库、加密供应商密钥所需的本机密钥、运行日志与任务工作树。目录 ACL 限制为当前用户和 SYSTEM。迁移设备时应关闭应用并一起备份该目录；不要只拷贝数据库，也不要将它上传到 GitHub。程序包不包含个人数据库或任何项目文稿。

文件数据库设置 `WRITE_DELAY=0`，在 API 写入完成前同步提交；这样即使紧接着关闭窗口并终止本次子进程，也不会依赖默认的延后刷盘窗口。测试直接在出现审批后关闭并重新打开真实文件数据库。

最终包复测曾捕获一次快速重启后审批未恢复，因而补入上述同步提交设置。修复后的完整启动、审批、重开、恢复和取消链路连续执行 3 次均通过，耗时共 70.456 秒；该失败与真实模型试验中的首轮 CODE 失败分别记录。

写入和命令调用默认停在审批处，批准后才执行。已有团队后端配置继续保留；登录页“运行环境与本机服务”中的“启用本机独立运行”可切换到内置服务，保存团队地址可切回。

本机独立模式的协议夹具测试覆盖：模型供应商保存与脱敏、聊天完成、代码补丁审批、关闭/重开后的任务与审批恢复、结果快照、取消、实例锁、子进程隔离和外部环境变量隔离。打包端到端测试实际使用内置 Java、文件 H2 和 Runner，并将 PATH 缩减至 Windows 系统目录后验证内置工具。Go 引擎、Java 控制面、桌面测试、56 项前端单测以及 20 组相关浏览器检查均通过。

2026-10-23 另用实际配置的 `gpt-6-sol` 做了小规模真实调用：两轮 CHAT/PLAN/CODE 连续场景和一次独立 CODE 场景，共 7 次任务，6 次达到验收条件，首轮 CODE 失败。第二轮连续场景及独立 CODE 均产生补丁，通过两次工具审批后，独立应用补丁并通过 5 项 Node 边界断言。期间没有修改生产代码以获得通过；独立 CODE 使用新对话，不能视为相同上下文的确定性重试。详见[评测记录](standalone-model-pilot-2026-10-23.md)。这些样本验证了实际模型、工具、审批和补丁链路，不代表普遍编程可靠性。
