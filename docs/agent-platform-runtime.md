# 智能体、记忆与 MCP 运行链

本文对应 2026-10-22 平台代码与 Windows 桌面发布构建。离线应用镜像导入/导出已补齐（仍需预装 Docker Desktop）；完整独立安装器和真实模型质量评测仍未完成；下载与历史验证见 [更新报告](update-report-2026-10-22.md)。

## Anthropic Messages 服务

模型服务现在可以选择 `anthropic` 协议。控制面使用 `x-api-key` 与固定版本头读取 `/models`，Runner 使用 `/messages`、SSE 事件和工具块协议；不会把 API Key 放进任务消息或界面回显。模型目录支持受限 `after_id` 分页，游标重复、超过 16 页或超过 1000 个模型会拒绝本次刷新并保留上一份目录。

Messages 的 `system`、用户/助手文本、`tool_use` 与 `tool_result` 会按 Anthropic 的消息结构转换。工具调用必须等完整 `message_stop` 和 `stop_reason=tool_use` 后才交给 Agent，`max_tokens`、错误事件、乱序块、重复工具 ID 和不完整 JSON 都会失败；因此截断响应不会执行半个工具调用。`input_tokens`、缓存读写 token 和输出 token 映射到统一用量模型，已报告的数据才计算费用。

设置页的“测试模型 → 验证工具调用”由用户手动触发。控制面发送一条固定短文本并要求返回 `proofcode_probe(ok=true)`，按所选协议验证完整工具结果，不执行工具。测试限 20 秒、256 KiB 响应；区分认证、权限/策略、限流/过载、请求/上下文、接口/模型、协议格式与连接问题。响应原文和密钥不会返回页面。它可能产生少量模型费用，结果只证明这次最小请求兼容；不自动检测所有能力，也不证明编程效果。

当前 Anthropic 适配限文本与普通工具调用，不发送图片、扩展 thinking、OAuth 或自动缓存策略；遇到未支持的块会明确失败。temperature 省略以兼容限制该参数的模型，不能用这一适配宣称固定温度 A–F 实验可比。供应商拒绝策略不会自动更换地址或绕过。

## 当前界面

Windows 桌面“运行环境”页可在登录前打开，检查 Git、Docker CLI、Docker 引擎、Compose 和 ProofCode 后端健康端点。检查有总时间预算，进程输出不回显，刷新失败时保留上次报告并明确标记其已过期。Web 版仅显示本机能力不可用，不操作宿主服务。

### 本机服务管理

先自行安装并启动 Docker Desktop。使用包含内置运行包的新构建时，可在“首次使用与依赖准备”点击“准备本机运行文件”，选择保存位置，创建新的 `ProofCode-runtime` 目录；或者自行准备源码与 `.env`，点击“选择部署目录”。目录中的 `compose.yml` 必须是普通文件，服务集合必须严格等于 `artemis`、`control-plane`、`postgres`、`redis`、`runner`、`web`。保存目录及该文件的 SHA-256，文件修改后必须重新选择；这是配置变化检查，不是任意 Compose 文件的安全沙箱，部署文件仍需用户信任。

“启动服务”显式执行 `docker compose --project-name proofcode ... up -d --build`，“停止服务”只执行 `stop`，不执行 `down`、删除卷或清理其他项目。操作前校验同名容器的 Compose 项目、目录和配置文件标签，发现归属冲突或孤儿容器时拒绝操作。服务状态读取实际 `docker compose ps --all --format json`；命令成功不等于所有服务健康。重复操作立即拒绝，切换页面保留操作状态，应用退出取消正在执行的命令。Docker 输出限 1 MiB，错误脱敏；不回显构建日志。手动“重新检查”读取当前状态，不是持续后台监控。

内置运行包免去手动复制部署源码与生成 `.env`，无需在宿主安装 Node、Go 或 Java；默认仍是源码构建方式，Docker 首次构建需要网络下载镜像和依赖。需要断网部署时，开发者可在已准备好 Docker 镜像的机器上运行 `desktop/export-offline-runtime.py`，生成含六个 Linux/amd64 镜像、清单和校验值的本地包；`desktop/package-offline-release.py` 可把它拆成 GitHub 支持大小内的引导 ZIP 与镜像分片 ZIP。目标 Windows 解压引导包和全部镜像分片到同一个文件夹后运行 `install.ps1`，脚本先验证 Compose、每片及组合镜像归档的 SHA-256、平台和内容 ID，再生成全新的本机密钥。导入不启动服务、不覆盖已有目录，桌面端检测到 `proofcode-offline.json` 后只执行 `up -d --no-build --pull never`。该包仍需要 Docker Desktop，不包含 Docker 本身或模型服务；模型请求和需要网络的外部 MCP 仍需网络。该管理器仅控制用户选定的部署，不自动启动任意目录或远程后端。

### 首次准备与内置运行包

`desktop/build-native.ps1` 在 Wails 构建前调用 `desktop/prepare-runtime-bundle.ps1`。打包器只收集 Docker 构建所需的 Go、Java、React 源码、迁移与明确列出的配置；不收集 Git 历史、`.env`、论文、Word/PDF、私有证据、测试数据或 `node_modules`。ZIP 包含每文件大小与 SHA-256 清单，生成到 Git 忽略的 `desktop/native/runtime-assets/runtime.zip`。开发者直接使用 `wails build` 前也应运行准备脚本，否则该开发版本仅能选择已有部署。

原生 `GetBundledRuntime` 只读取内嵌数据，不访问 Docker 或网络。`PrepareBundledRuntime` 校验清单、文件 hash、路径、普通文件类型和展开体积，在临时目录展开；只发布到尚不存在的 `ProofCode-runtime`，拒绝覆盖旧目录。`.env` 为服务认证、Runner、数据库、消息代理和数据加密分别生成独立的 256 位随机值，不包含模型 API Key。准备过程中仅写新目录和桌面部署选择，不改变后端地址、账户或既有数据密钥；取消和失败保留原配置。

代码修改默认允许、命令与测试默认关闭，用户选择写入生成的 `.env`；实际任务仍受模式、白名单与批准流程约束。准备完成后需明确点击“启动服务”，注册/登录后再配置模型。模板只向 `127.0.0.1` 发布 Web/API 端口，数据库与消息代理不发布宿主端口。页面提供 Docker/Git 官方安装说明链接，只有用户点击才打开。

### 后端地址配置

页面可保存 ProofCode 控制面根地址，支持 HTTP/HTTPS、自定义端口和远程后端；不接受账号密码、额外路径、查询参数或片段。地址优先级为本机 `runtime-connection.json`、启动环境 `PROOFCODE_CONTROL_PLANE_URL`、默认 `http://127.0.0.1:8080`。保存不发起网络请求，需主动重新检查连接；代理禁止跟随重定向。

更换目标地址前清除旧登录 session 和远程导航选择，保留编辑器草稿；新后端需要重新登录。配置读取失败有明确提示，可重新保存修复，不静默切换地址。本机配置保存在用户的 ProofCode 配置目录，与项目源码分离。模型服务的 API 地址和密钥仍在登录后的模型设置中配置。

打开一个工程对话，顶部的“智能体与记忆”管理该工程的配置。智能体可以保存名称、工作方式、工具名称白名单、MCP 服务和只读约束；对话旁的选择框保存当前对话的智能体。智能体可选绑定当前账户拥有的模型服务及目录中的模型；未绑定时沿用输入区选择。绑定时输入区明确显示并锁定模型，切回默认智能体恢复原手动选择。服务或模型失效时阻止发送，不静默替换；服务端对过期界面提交的模型不匹配返回冲突。已有任务的角色、模型和加密服务连接固定，编辑或删除配置不改变幂等重发和任务重试。

个人偏好与项目记忆由用户明确保存，不自动收集聊天内容。“个人偏好”保存账户级的回答语言、回答方式、编码偏好和协作方式，在同一账户的不同项目生效；当前请求和项目约束优先。可以清空并保存来停止引用；版本冲突会拒绝覆盖，读取失败时不能直接保存。启用的普通项目记忆按当前问题的词项和中文双字片段匹配，固定记忆优先；最多 8 条、共 12000 字符。用户可预览引用、编辑、停用或删除，运行详情展示作用域、版本、匹配得分和引用原因。它是确定性文本检索，不是 embedding 或已经验证效果的学习系统，记忆作用域为工程。

任务创建时，控制平面保存角色、权限和实际引用的记忆原文及来源版本，SHA-256 随 Outbox 派发。Runner 持有效任务租约取得快照，核对哈希后使用。编辑、删除、切换智能体不会更改已经开始的任务；重试和批准后恢复沿用原快照。运行详情可展开本次角色和记忆来源。

只读约束在工具调用时检查真实 Risk，阻止写入、命令和外部 MCP 执行。工具白名单同时约束主任务和只读子任务，不能通过子任务绕过。

## Skills 工作流程

“智能体与记忆 → Skills”支持创建、编辑、停用、删除，以及导入/导出带 YAML `name`、`description` 的 `SKILL.md`。默认智能体提供本项目所有已启用条目；自定义智能体只提供明确勾选的条目，未勾选时不继承默认目录。停用或删除被引用条目后，新任务会要求调整绑定；已开始任务、幂等重发和重试保留原正文、版本与 SHA-256。

模型的初始提示只包含可用名称、简介和版本等元数据。`skill_read` 从任务快照读取正文，支持 `startLine`、`maxLines` 和 `nextLine`，默认 120 行、最多 200 行，每页正文不超过 16 KiB。CHAT 仅增加这个读取保存说明的工具，最多 8 步；PLAN 仍禁止修改和命令，CODE 沿用原审批机制。设置工具白名单时必须包含 `skill_read`，技能绑定本身不能扩大工具权限。运行详情里的“可按需读取”目录不代表模型已经使用，实际读取由工具事件记录。

每项目最多保存 100 个 Skills；每任务最多 16 个、正文共 80000 字符；单条简介最多 500 字符，正文最多 24000 字符，单行最多 16000 UTF-8 字节，整个智能体快照最多 480 KiB。超限明确拒绝，不静默截断。YAML 使用安全构造器，拒绝重复字段、对象标签和集合别名；导入不会执行脚本、联网下载或自动安装依赖。当前只导入文档正文，不导入 `scripts/`、`references/` 等配套文件，也不自动扫描本机技能目录或提供技能市场。

设计参考为本地 OpenCode `src/tool/skill.ts` 的按需加载方式，对应 [上游源码](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/skill.ts)。参考文件仅作为代码资料，不作为当前任务指令执行。

## 规划与运行中补充

任务支持 CHAT、CODE 和 PLAN。PLAN 使用只读工具调查工程，不运行命令、修改源码或连接外部 MCP 服务；仍可通过 `update_plan` 保存内部规划状态。普通代码任务也可维护持久步骤，包含待处理、进行中、完成和受阻状态；界面展示计划及进度。该状态来自 Agent 更新，不是独立验证器对完成情况的保证。

规划任务成功后，“用此方案创建代码任务”将原目标、方案和来源填入输入框；用户检查并发送后才创建执行任务。它不会自动执行方案，已有草稿会保留。

运行中代码或规划任务可以提交补充指令，服务端按任务尝试保存顺序和幂等键。Runner 在完整工具调用组结束、下一次模型调用前加入上下文，先保存检查点再确认交付；恢复时避免重复加入。界面区分等待交付和已交付，交付不代表模型已经执行要求，也不会撤销先前动作。任务结束后不能继续追加。

## 接入 MCP 服务

Runner 管理员在 `RUNNER_MCP_SERVERS` 设置 JSON 数组，例如：

```json
[{"name":"workspace","command":"proofcode-mcp","args":["-root","."]}]
```

Compose 已传入此变量，Runner 镜像构建 `proofcode-mcp`。在智能体的“MCP 服务别名”填入 `workspace` 后，新代码任务启动该服务；未配置的别名明确报错，不能自行指定运行任意宿主程序。`command` 和 `args` 是数组化程序参数，不经 shell 执行。凭据仅放在私有环境配置的 `env` 中，不进入角色配置或队列。

服务进程的工作目录为任务隔离工作树。初始化与发现各有 15 秒上限，调用上限 60 秒；任务结束关闭连接与主进程。分页发现限制 32 页、256 工具，服务最多 16 个；工具统一使用 `mcp__服务别名__工具名称`，限定 64 字符。工具调用经过正常请求、批准、执行、完成/失败和检查点链，即使 Runner 开启自动执行也仍需显式批准外部 MCP 调用。只读模式拦截外部工具。

服务器程序是管理员信任的软件，继承 Runner 的操作系统权限；工作树并不是外部程序的系统沙箱。本地 stdio 仍由管理员维护，尚无面向用户的可执行服务安装向导。

### 用户自己的远程服务

“智能体与记忆 → MCP 服务”现在支持添加、编辑、停用、删除项目内的远程服务。填写别名、Streamable HTTP 地址和可选 Bearer 令牌，然后在智能体中勾选。保存配置不会连接服务；新代码任务启动时进行初始化及分页发现。普通聊天、PLAN 和只读智能体不读取远程令牌，也不连接外部服务。只读智能体不能靠勾选远程服务获得执行权限。

令牌以 AES-GCM 加密，列表只返回是否已保存；输入框保存后清空。更换地址必须重新输入或明确清除原令牌。任务保存服务 ID、版本、地址及加密令牌快照；恢复沿用原连接，只有持有效任务租约的 Runner 可获取解密连接，令牌不进入模型角色提示或队列。停用/删除阻止新任务引用，不撤销已经固定的任务凭据；需要即时撤销时应在服务商端吊销令牌。

HTTP 传输处理 POST JSON 和 SSE 响应、会话 ID、协议版本、分页工具目录以及会话关闭。远程与本地服务共享数量、超时、审批和恢复时目录一致性检查。重定向不跟随，RPC 错误原文不回显。默认只允许公共地址；确需本机/内网服务时管理员设置 `PROOFCODE_MCP_ALLOW_PRIVATE_HOSTS=true`，Compose 同时传给控制平面和 Runner。Runner 在建立连接时校验所有 DNS 结果，并直接连接检查过的 IP。

远程 MCP 也支持下述 OAuth 登录。当前未实现旧版独立 SSE 端点、后台 GET 通知流及服务资源/提示模板。保存成功不等同于服务可用；可以按下面的流程主动诊断。参考：[OpenCode MCP 实现](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/mcp/index.ts)，本地参考文件位于 `D:/coding-agents-catalog/repositories/anomalyco/opencode/packages/opencode/src/mcp/index.ts`。

### OAuth 登录

1. 管理员设置 `PROOFCODE_MCP_OAUTH_REDIRECT_URI` 为浏览器能够访问的固定控制面 callback 地址，路径为 `/api/mcp/oauth/callback`；必须和授权服务注册的地址完全一致。默认使用 `http://localhost:8080/api/mcp/oauth/callback`，非本机部署需 HTTPS。该变量已通过 Compose 传入控制面。
2. 保存远程 MCP 服务后展开“OAuth 登录”，填写已注册的客户端 ID、可选客户端密钥及 scope，点击“保存 OAuth 配置”。暂不自动注册 OAuth 客户端；公共客户端可不填密钥。清空客户端 ID 后保存可移除 OAuth 配置。修改服务配置或 OAuth 配置后，新任务需要重新授权。
3. 点击“连接 OAuth”，在服务商页面完成授权。弹窗不可用时点击“打开授权页面”。ProofCode 会轮询显示授权状态；等待时可“取消授权”，取消或失败后可重新连接。授权完成后可主动“诊断连接”，再把服务勾选到智能体中。

使用 MCP protected-resource metadata 和 authorization-server metadata 发现端点，要求 PKCE S256，以 authorization code 换取令牌。当前不支持动态客户端注册和 device-code 流程。发现与 token 请求沿用受限 HTTP 客户端：不使用环境代理、不跟随重定向、连接时校验 DNS/IP；公共服务要求 HTTPS，内网服务仍需管理员开启既有内网开关。

state 仅保存哈希，有效期 10 分钟且一次性消费；callback 同时校验配置版本，拒绝重放、取消和过期授权。客户端密钥、PKCE verifier、access token 和 refresh token 加密保存在控制面；公开状态及浏览器存储不保存 token。任务固定授权引用和服务版本，不把明文 token 放入模型上下文。Runner 通过有效任务租约获取令牌，使用前检查到期时间，提前刷新并保存服务商轮换的 refresh token；没有 refresh token 或刷新失败时明确要求重新连接，不自动改用其他认证方式。

状态与配置接口为 `/api/projects/{project}/mcp-servers/{id}/oauth?version={savedVersion}`（GET/PUT），显式授权/取消为其 `/begin` 和 `/cancel` 子路径（POST）。仅账户所属项目可访问；callback 不依赖 ProofCode 账户 cookie，以一次性 state 校验。现有任务保持原授权引用；需要立即撤销访问时，应在服务商端吊销凭据。

当前验收使用真实 Go helper、本地 HTTP 授权服务和浏览器 API fixture，没有连接真实 OAuth 服务商。兼容性范围与测试结果见 `agent-platform-upgrade.md`。

### 诊断连接和预览工具

保存服务后，点击“诊断连接”，检查当前保存版本的初始化及分页工具发现。诊断不会调用 `tools/call`，不会在保存、打开设置或切换智能体时自动触发；停用的服务也可以主动诊断。修改表单后需要先保存，旧结果立即清除。服务版本、检查时间、耗时和协商协议随结果展示；工具可以按名称/说明搜索，展开后查看完整名称和输入 JSON Schema。服务说明仅作为文本显示，不执行 HTML 或脚本。

诊断只证明当次连接和目录可读取，不证明所有工具的执行效果。远程认证、403 权限/策略拒绝、重定向、限流、网络/DNS、内网策略、超时、协议及工具目录错误分别显示；远程的 401/403 放在正常诊断结果中，不使用户退出 ProofCode。结果不能绕过工具调用审批。

控制平面通过固定 Go 程序 `proofcode-mcp-inspect` 复用 Runner 的实际 HTTP 传输，包括连接时 DNS 校验、直接拨号到已检查 IP、禁止重定向及内网开关。令牌只通过子进程 stdin 传递，不放进命令参数、日志或页面；返回的工具名称、描述及嵌套 schema（包括键名）进行令牌脱敏。只执行初始化、初始化通知、目录分页和会话关闭。仍遵循 32 页、256 工具及完整工具名最多 64 字符的限制。

单次 Go 检查最多 15 秒，关闭会话最多额外 2 秒；父进程默认 20 秒终止未结束的程序。每个控制平面最多同时诊断 2 个服务，超出返回繁忙，不排队占用请求。stdin 最多 16 KiB、目录预览最多 512 KiB、子进程 stdout 最多 1 MiB。过大目录明确拒绝，不显示部分结果。诊断前后查询保存版本；期间修改或删除服务会使结果失效，HTTP 请求中的实体缓存不会代替最后的数据库版本检查。

接口：`POST /api/projects/{project}/mcp-servers/{id}/probe?version={savedVersion}`，只诊断当前账户拥有的项目服务，返回 `Cache-Control: no-store`。没有请求正文，URL/令牌来自已保存配置；响应为 `savedVersion` 和 `result`，不含凭据。配置已变化返回 409，可用“重新加载服务”恢复；加载失败时禁用编辑和诊断，避免用不完整目录覆盖设置。

Compose 构建现在自动把 helper 放进控制平面镜像。Dockerfile 使用仓库根构建上下文，根 `.dockerignore` 只允许控制平面源码与必要 Go 源码进入，排除 Git 历史、论文、凭据及本地产物。本机直接运行控制平面时，先执行：

```powershell
go -C agent-engine build -o ../.proofcode/bin/proofcode-mcp-inspect.exe ./cmd/proofcode-mcp-inspect
$env:PROOFCODE_MCP_INSPECT_BIN = (Resolve-Path .proofcode/bin/proofcode-mcp-inspect.exe).Path
```

程序路径由管理员配置，不接受项目或请求传入的程序/参数；未安装时返回明确的“诊断程序未安装”结果。修改该环境变量后需重启本机控制平面。

## 通用工具服务

本机构建：

```powershell
go -C agent-engine build -o ../.proofcode/bin/proofcode-mcp.exe ./cmd/proofcode-mcp
```

任意兼容 MCP 客户端可把该 exe 作为 stdio 服务，传入 `-root <工程路径>`。默认只暴露文件读取、批量读取、目录、搜索、文件信息、Git 查看和工具发现。`-allow-write` 显式开放结构化补丁；`-allow-programs go,git,pytest` 显式开放受限命令。开启修改的宿主客户端必须提供批准流程。文件、凭据路径和程序白名单沿用已有工具策略。

用户自定义工具可以采用兼容的 stdio 服务加入管理员目录，或自行部署 Streamable HTTP 服务并在项目设置中添加，无须修改主 Agent 循环。设置页的“创建自己的工具服务”包含源码模板生成命令、工具模块位置、HTTP 认证和 Docker 网络提示；展开不会发起网络请求。

仓库新增 [`mcp-service/`](../mcp-service/README.md)，使用官方 MCP SDK 提供独立 Node 服务和模板生成器。`npm run init -- --directory <新目录>` 复制明确的运行文件及锁定依赖，生成新的本地 `.env` 随机 token、工具示例和知识目录，拒绝覆盖已有目录；生成后的服务不依赖原源码路径。工具模块导出名称、说明、对象 JSON Schema 和异步 execute，严格校验参数并限制并发、响应体积与协作式超时，错误不回显异常原文，输出遮蔽配置的凭据。HTTP 使用 Bearer 验证、显式 Host/Origin 白名单及请求体限制，以随机会话 ID 关联初始化、工具调用、跨请求取消和 DELETE 关闭；最多 64 个会话，空闲 10 分钟后清理，不提供后台 GET 通知流。stdio 使用同一工具目录。自定义模块是拥有者信任的代码，导入和 check 可执行模块顶层代码，不是系统沙箱。

随附 `knowledge_search` 查询所选目录内的 Markdown/文本，返回路径、行号和片段，是可修改的本地词项检索例子，不是 embedding 检索。不会自动读取用户工程、论文或其他磁盘目录。工作台实际调用仍按现有外部 MCP 执行风险进入审批和检查点链。模板生成器解决手工创建服务的起步问题，尚无用户本地第三方程序安装向导，也不会从网页配置运行任意本机程序。

完整桌面构建会执行 `desktop/prepare-mcp-template.ps1`，内嵌只含 14 份白名单源码及哈希清单的模板 ZIP。MCP 设置内的创建表单可选择本机保存位置，生成独立工具目录；HTTP 默认只监听回环，显式勾选 Docker 访问才监听所有网卡并允许 `host.docker.internal`。生成后仍需 Node.js 22+、手动运行给出的 npm 命令和管理员内网 MCP 开关。明确点击填入表单及保存后才添加项目服务；stdio 仍由管理员配置。向导不会自动安装依赖、执行模块、运行服务或改变当前后端连接。

## 聊天旁的文档与浏览器预览（2026-10-22）

工作台右上角的“预览”展开右侧工作区，“浏览器”直接打开其中的项目浏览器，聊天不离开当前页面。文件夹按钮可打开本机 Markdown、TXT、PDF、Word .docx；文件页已打开的 Markdown/TXT 也可点“预览”，按当前编辑草稿生成只读预览，不写回文件。最多保留 8 个文档标签，单文件最多 32 MB、文本最多 2 MB、文档合计最多 96 MB。旧版 .doc 需要先另存为 .docx。
