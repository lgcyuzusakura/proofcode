# ProofCode 更新报告

日期：2026-10-13

## 本次实现

本次更新把 ProofCode 从单一的本地调试入口推进到可配置的编程智能体工作台：

- 增加账户注册、登录、登出和会话失效处理，并在任务 WebSocket 发送前再次校验会话与工程归属。
- 增加模型服务管理，支持 OpenAI Chat Completions 和 Responses 两种协议、模型目录读取、模型显示名以及加密保存的 API Key。
- 增加按模型保存运行参数。默认上下文为 128000 Token，默认输入上限为 16000 Token，默认输出上限为 2048 Token；参数可以留空使用默认值。
- 增加可选计价区间。输入、输出、缓存读、缓存写价格均不是必填项，支持按输入 Token 上限配置多档价格；未配置完整价格时费用显示为未知，不伪造费用。
- 增加运行用量展示：总用时、首字时间、请求耗时、输入/输出 Token、缓存读写 Token、Token/s、计价区间和估算费用。计时来自本地，Token 和缓存来自服务商，价格来自用户配置；费用为估算。
- 增加上下文压缩强度配置（轻度、均衡、强力），并将压缩、预算和受保护内容的约束留在 Runner 侧执行。
- 改进聊天工作台的滚动容器、消息定位、工具活动、运行资源、模型设置和移动端布局。
- 保留了可追溯执行链：任务配置快照、attempt、工具事件、批准和验证结果仍由服务端记录。

## 上下文管理方案

`docs/context-management-upgrade-proposal-2026-10-13.md` 是下一阶段的设计方案，不代表本次已经交付逐条排除上下文功能。方案提出 Transcript、Context View 和 Context Pack 三层模型，要求排除来源后使摘要和记忆失效并从原始材料重建，且 CHAT、CODE 和恢复执行统一使用不可变快照。

## 默认值与边界

模型设置默认值来自 Runner 的共享配置：128k 总上下文、16k 输入、2048 输出。输入和输出加保留空间不得超过总上下文。价格允许为空；缓存命中不等于本地迁移服务商 KV cache，界面只展示 provider 返回的实际缓存用量。

## 验证

- 本轮前端 22 项测试全部通过，Web 与桌面共享前端生产构建通过。构建仍提示 Monaco/代码编辑资源包体积较大，尚未进行全面拆包优化。

- 本轮控制面完整 Maven 测试：81 项，72 项执行通过，9 项依赖外部数据库/Redis 的 Live 用例跳过，失败和错误均为 0。使用单个 `--rm` 临时验证容器，执行完成即移除。
- Agent Engine 全量 `go test -count=1 ./...` 和 `go vet ./...` 通过。此前 Windows 持久化文件锁出现过偶发失败，本轮重跑未复现，不能据此宣称并发稳定性研究完成。

- 本轮清理了 ProofCode 的旧 Docker 测试环境，删除 21 个容器和 5 个网络，保留数据卷；其他项目容器未改变。
